# AdaMAS-unit：可进化的预算规划者（设计扩展 v0.2）

Nov 5, 2026 · 在 v0.1 设计上扩展，状态：设计稿

## 0. 一句话

v0.1 解决的是"一次多阶段执行如何在硬预算下跑通"。v0.2 把一次完整的多阶段执行称为一个**轮回**，让**预算规划者**在轮回与轮回之间进化：同一道题再做一次时，资源安排更长远——不耗尽、修复次数和步数够用、压缩次数合适、最终代码一定能提交，并把纠错与时间花在更重要的单元上。

**进化的只有预算规划者。** 构建者、出题者、修复者在一切轮回中保持固定，且看不到任何上一轮回的信息。这样轮回之间的变化只能归因于预算安排。

## 1. 对 v0.1 的审阅

### 1.1 方向是对的

- 单元只传代码、去掉产物槽和子图，正好消除了最近一次测试里废掉里程碑的产物槽冲突；
- "没过门也带着代码继续"解决了"一个不过、全部阻塞"；
- 用硬预算和固定修复次数替代开放式修复搜索，直接针对"开销大、提升小"（约 70% 开销花在修复候选上）；
- 对照组已包含"相同总预算下的单个会话续跑"，补上了上一次对比最大的缺口。

### 1.2 需要补强的地方

1. **回归卷与"继续模式"打架。** D3 选择继续模式后，前面未过门单元的考卷会在后面每一个门里反复失败。门的结果必须分三栏记录：本单元新卷的失败、旧卷中继承来的失败（提交时就已失败）、旧卷中的新回归（提交时通过、现在失败）。只有第一、三栏能触发本单元的修复；第二栏是否值得花钱去修，正是预算规划者要判断的事（见 §5.3）。
2. **平均分配忽略了单元难度。** 基本额度 = 剩余 ÷ 剩余单元数，是没有信息时的合理起点，但它也正是进化要去改善的对象。
3. **规划者只看当前轮回，没有长远信息。** v0.1 的规划者只能看到当前账本，它不知道"第 4 单元在这道题上往往需要大量时间"这类只有经历过才知道的事。这是 v0.2 要补的核心。
4. **"最终能提交"应当是进化学会的能力，而不是基础版自带的保证。** 基础版不预留任何提交储备、不做任何提交修复，预算耗尽时就按当时的代码评分——哪怕包都导入不了。这样"资源管理得好、最终一定能提交"就成为进化要证明的贡献之一（见 §4.1、§5.4）。为了度量这项能力，每个轮回结束时都机械地做一次提交检查，但**只观测、不采取任何行动**，对基础版不构成帮助。
5. **每个轮回重新出题会让尺子变化。** 出题者每次写出的考卷不同，轮回间的门结果就不可比。同一道题在多个轮回间应**冻结考卷**：第 0 轮回出题一次，之后重用。这也顺带省下了后续轮回的出题成本。
6. **框架更换带来混淆（D7）。** 从 Codex 换到 mini-swe-agent，会让新结果与已有的 Codex 数据不可比。所有对照组（单会话续跑、旧 AdaMAS）都必须在同一框架下重新跑；"直接用已有数据"只在框架不变时成立。
7. **智能体自己提追加申请，会偏向多要。** 申请只是信号之一；规划者应依据可核实的进展指标（门结果是否在改善、最近 N 步是否有代码变化）做判断。

## 2. 轮回：定义与隔离

**轮回**：用一个固定的预算策略，把一道题从空仓库完整跑完所有单元。第 k 轮回用策略 π\_k，结束后用这次的记录产生 π\_{k+1}。

为了让轮回间的改变只来自预算，必须守住以下隔离：

| 跨轮回保留 | 跨轮回不得保留 |
| --- | --- |
| 预算规划者的记忆与策略 | 上一轮回的代码、单元输出 |
| 各单元冻结的考卷（作为不变的尺子） | 构建者、修复者的任何对话或经验 |
| 单元划分（冻结计划） | held out 的任何内容 |

构建者和修复者每一轮回都从零开始。否则轮回间的提升可能来自"记住了上次怎么写"，而不是预算安排得更好。

## 3. 形式化

仓库 r 有 n 个单元。总预算为一个向量（token、等待时间、压缩次数、修复次数）：

```latex
B = (B^{tok}, B^{time}, B^{cmp}, B^{rep})
```

预算策略 π 给出两类决定：每个单元的**先验额度**（单元开始时分去多少），以及运行中的**追加审批规则**：

```latex
\pi:\ (\text{账本状态},\ \text{单元特征},\ \text{轮回记忆})\ \mapsto\ (a_1,\dots,a_n,\ \text{审批规则}),\qquad \sum_i a_i \le B
```

基础策略 π\_0 平均分配、不预留提交储备。是否为收尾留出资源、留多少，由进化自己决定（§5.4）。

一个轮回的结果是最终代码 c 和一组过程记录。进化的目标是：在预算约束和"必须可提交"的约束下，最大化轮回得分：

```latex
\max_{\pi}\ \mathbb{E}\left[ S(c_\pi) \right]\quad \text{s.t.}\ \ \text{cost}(\pi)\le B,\qquad S = w_1\cdot \text{pass}_{\text{frozen}} + w_2\cdot \text{submittable} + w_3\cdot \#\text{gated units}
```

每一轮回之后：

```latex
\pi_{k+1} = \mathrm{Improve}\left(\pi_k,\ \text{logs}_{\le k}\right),\qquad \text{接受当且仅当}\ \hat{S}(\pi_{k+1}) > \hat{S}(\pi_k) + \epsilon_{noise}
```

不接受时保留现任策略（与 AdaMAS "不低于现任才提交"同一原则）。

## 4. 进化得分用什么信号

### 4.1 可提交：只观测，作为进化目标

- **提交检查**（机械，不调用模型）：包能导入；文档点名的公开名称能导入；全部冻结考卷能收集（不要求通过）；命令行入口可运行（若文档有）。
- **在基础版里只观测、不行动**：每个轮回结束时跑一次，结果记为 submittable ∈ {0, 1}，不触发任何修复、不预留任何资源。基础版和对照组都按同样方式测量，谁都不因它得到帮助。
- **它是轮回得分的一项**（§3 中的 w\_2），也是 §4.3 诊断里"耗尽导致不可提交"的判据。规划者要靠自己学会：在什么时候、为收尾留出多少 token、时间和修复次数，才能保证最终可提交。

这样，"合理管理资源、保证代码最终能提交"就成为可度量的进化贡献：比较 π\_0 与进化后策略的 submittable 比例、以及耗尽发生的位置。

### 4.2 轮回得分 S：以内部尺子为主

得分不直接用 held out，而用跨轮回不变的冻结考卷：

- 最终代码在**全部单元冻结考卷**上的通过率（主项）；
- 过门单元数；
- 提交检查是否一次通过（未动用储备）。

为什么不用 held out：同一道题反复轮回时，用 held out 做选择就是对着测试集调参。若确需 held out 信号，沿用已有做法：对半分成反馈半与评估半，只用反馈半且只传一个数字，评估半只用于最终报告。

需要提前承认的局限：冻结考卷是自己出的，它与 held out 的关系在之前的实验里并不紧密。所以轮回得分上升只说明"在同样预算下做完了更多文档写明的事"，是否转化为 held out 提升要用评估半单独验证。

### 4.3 过程诊断：告诉规划者"哪里分配错了"

这些是给进化提方向的信号，全部从账本算出，不需要模型判断：

| 诊断 | 判定 | 含义 |
| --- | --- | --- |
| 耗尽点 | 哪个单元触发了总预算耗尽 | 前面花太多，或该单元本身太贵 |
| 进展中被截断 | 会话因额度停止时，最近一段仍在改善门结果 | 该单元分少了 |
| 修复上限仍失败但每次在进步 | 用满 3 次修复，失败数单调下降 | 修复次数不够 |
| 修复无效 | 修复前后失败数不变 | 该单元在浪费修复预算 |
| 剩余未用 | 单元结束时大量额度未用 | 该单元分多了 |
| 压缩后退化 | 压缩后门结果变差或重做已完成的工作 | 压缩太早或太多 |
| 超窗停止 | 压缩次数用完后会话超窗停止 | 压缩次数太少 |
| 无产出循环 | 最近 N 步无代码变化且门结果不变 | 应提前收回额度 |

## 5. 规划者学什么、怎么存

### 5.1 三层内容

1. **本题预算表（结构化）**：每个单元的先验额度份额（各项预算占总量的比例）、修复上限、压缩上限。只用于同一道题的下一轮回。
2. **通用规则（skill 文档条目）**：从多道题的轮回里总结出的规律，如"整合单元至少留两成时间"、"第一单元修复无效时不要追加"。每条带试用 / 启用 / 淘汰状态，可用于新题。
3. **轮回摘要（记忆）**：每轮回一条结构化记录：用的策略、各单元各项用量、§4.3 的诊断、轮回得分。它是改进步骤的输入，不含任何代码。

### 5.2 改进步骤（轮回之间）

1. **诊断**（程序）：从账本算出 §4.3 的全部诊断，以及本轮回的 submittable；
2. **提议**（一次模型调用）：预算进化者读本题预算表、轮回摘要、诊断，提出新的预算表；可以提议 0–2 条通用规则，例如"最后一个单元结束前保留一份收尾预算"；
3. **机械校验**：总和不超过 B；单元份额不低于保底值；单次改动幅度有上限（如每个单元份额最多 ±30%），防止大跳变把噪声当信号；
4. **下一轮回使用新表，按 §3 的接受规则决定保留还是回滚。**

### 5.3 运行中的审批（轮回之内）

v0.1 的规划者审批保留，但输入增加两样：本题预算表（先验）与启用的通用规则。审批仍受机械上限约束。另加两类决定：

- **是否花钱修继承来的失败**（§1.2 第 1 条的第二栏）；
- **提前收回**：发现"无产出循环"时可以提前结束会话，把额度还给账本。

### 5.4 从规划者的经验晋升为 harness 机制

规划者学到的规则，有一部分最终应当固化进 harness，成为后续版本的固定机制——这正是本工作 RSI 的产出形式：

1. **候选**：一条通用规则在多道题、多个轮回中处于启用状态，且带来可测的改进（例如"为收尾预留资源"使 submittable 从 x 升到 y、耗尽点后移）；
2. **检验**：在 E3（没做过的题）上，带这条规则与不带它配对比较，改进仍然成立；
3. **晋升**：把它写成 harness 里的机械规则（例如固定的收尾储备、收尾检查加一次修复），版本号加一，并记录来源轮回与证据；
4. **晋升后的对照**：此后所有对照组仍以 π\_0（无该机制）的基础版作为下限，同时报告"基础版 + 晋升机制"的效果，证明这项能力来自进化而不是先验设计。

## 6. 噪声与单元重放

同一道题重复运行的波动很大（之前 imapclient 两次 0.30 与 0.14、python-hl7 0.36 与 0.45）。轮回间只跑一次就判定好坏，很可能把运气当成进步。两个对策：

1. **先测噪声**：第 0 阶段用同一个策略对同一道题跑 3 个轮回，得到 ε\_noise；之后的接受必须超过它。
2. **单元重放**（本设计的一个重要优势）：由于单元只传代码，每个单元开始时的代码快照就是一个天然的检查点。要回答"给单元 k 多分 X 有没有用"，不必重跑整道题，只需从单元 k 的快照出发，用不同额度各跑几次该单元，比较冻结考卷结果。这把昂贵的整轮回对比，变成便宜的局部配对实验，用来估计每个单元"多一份预算的边际收益"。

单元重放只用于估计，不反向写入任何轮回的结果。

## 7. 安全与隔离

- 预算规划者与进化者**不能**：改总预算、改考卷或门、改单元划分、看到任何代码或 held out 内容；提交检查的判据也不能改，它只是观测；
- 它们的 token 单独记账（管理开销），并设上限（如不超过总预算 2%）；
- 沙盒规定、密封规定、"缺东西即报错停止"、每次报告含沙盒越界警告，全部沿用；
- 每个轮回用独立的状态目录，停进程只按明确的进程号或进程组。

## 8. 实验计划

| 阶段 | 内容 | 回答的问题 |
| --- | --- | --- |
| E0 | v0.1（平均分配）在同一道题上跑 3 个轮回；并在同一框架、同一预算下跑单会话续跑对照 | 轮回噪声有多大；单元化本身是否优于单会话 |
| E1 | 同一道题上进化 5 个轮回；配合单元重放 | 预算规划者能否在同一题上学会更好的安排（耗尽减少、轮回得分超过噪声） |
| E2 | 用评估半 held out 验证 E1 的最终策略 | 内部得分的提升是否转化为 held out 提升 |
| E3 | 把启用的通用规则用于没做过的题（只带规则，不带预算表） | 学到的是可迁移的规划能力，还是只是这道题的资源档案 |

E1 成功只说明"能为做过的题优化资源"——这在重复任务场景中有实际价值；要声称规划能力的自我改进，需要 E3。第一批题建议从最近 5 道困难题中选 2 道做 E0–E1，其余留作 E3。
