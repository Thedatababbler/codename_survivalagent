# 如何使用现有框架（v0.2，2026-11-05）

> v0.2 更新：配合 DESIGN v0.2（可进化的预算规划者）。新增内容包括：冻结考卷、逐条门结果、会话中途测量、提交检查、
> held out 对半拆分、规则状态格式，以及 §4 新增的轮回、诊断、进化者、单元重放模块。

> 本文说明 AdaMAS-unit 要从 AdaMAS（`/root/projects/AdaMAS`，分支 `rsi`，34276d69）和 mini-swe-agent 里
> 拿什么、不拿什么、怎么接起来。只写到模块和接口层面；具体实现时，以当时的代码为准，先核对再动手。

## 1. 总原则

- **复制后裁剪，不直接引用。**需要的 AdaMAS 模块复制进本项目，AdaMAS-single 也是这么做的。这样两边各自修改，互不影响。复制时在文件头注明来源路径和 AdaMAS 的提交号。
- **不改 AdaMAS。**本项目的会话不编辑、不推送 AdaMAS 和 AdaMAS-single。
- 沙盒规定在本项目同样适用，见 `CLAUDE.md`。

## 2. 从 AdaMAS 拿什么

### 2.1 原样复制（必须）

### 2.3 门要改成逐条结果

AdaMAS 的门只判断通过或失败，DESIGN v0.2 需要它给出**每条用例**的结果：

- 每个单元提交时，记下本单元门在每条用例上的结果，作为基线；
- 之后的门按这个基线分成三栏（DESIGN §4.4）：新卷失败、继承失败、新回归。

用例的标识沿用 pytest 的节点名。考卷冻结后，节点名在各个轮回之间保持稳定。

### 2.4 提交检查

- 只用设计文档和冻结考卷，不碰 held out，所以不需要放进 `scripts/sealed/`。
- 可以借用的部分：
  - "文档点名的名称"的提取，复用 AdaMAS 的读文档函数（`scripts/sealed/nl2_ceiling.py` 的 `_docs_text`，它只读设计文档）；
  - "考卷能收集"，用 `pytest --collect-only`，在沙盒的评分模式下运行，做法和 `heldout_load_survey.py` 相同，只是对象换成冻结考卷。

### 2.5 不拿

调度器和子图（`control/ready_scheduler.py`、`runtime/`、`realbench/subgraph_builder.py` 的图结构部分）、产物槽和输入汇总（`control/input_assembler.py`）、修复搜索（`control/fast_loop/`）、进化和记忆（`control/evolution/`、`memory/`）、Codex 后端（`backends/codex_sdk.py`）。

这些正是新设计要替换的部分。产物槽冲突、子图卡死等缺陷也都出在这里。

## 3. mini-swe-agent 怎么用

### 3.1 版本

固定版本：mini-swe-agent 2.4.6（GitHub 提交 04d809c，2026-09-03），用 pip 安装并锁定版本，不改它的源码。所有定制都放在本项目里，用继承实现。

### 3.2 它自带什么

- 智能体循环（`agents/default.py`，约 190 行）：每一步先检查限额，再调用模型，再执行动作。
- 限额：步数 `step_limit`、按美元计的 `cost_limit`、墙钟 `wall_time_limit_seconds`。限额每一步都从配置读，运行中修改会立刻生效。
- 动作只有 bash 命令，统一通过 `Environment.execute()` 执行，每条命令有超时。
- 每次模型回复都保存 `usage`，完整轨迹存成 JSON。

### 3.3 它没有、要在本项目里补的

| 要补的 | 怎么接 |
|---|---|
| 按 token 计的会话额度和总预算 | 继承智能体类，重写"调用模型"这一步：调用前向账本查剩余（含余量），调用后用回复里的 `usage` 报账。不用它的美元限额，它不认识我们模型的价格。 |
| 等待时间与全局账本联动 | 用账本的剩余时间设置它的墙钟限额和单条命令的超时。 |
| 上下文压缩和次数 | 在同一个重写点检查上下文大小，超过阈值时摘要较早的消息，并向账本扣一次压缩次数。 |
| 预算追加申请 | 约定一条特殊命令（例如 `request_budget …`）。环境类在执行前拦下它，转交预算规划者，把批复写回会话限额和账本，再把结果作为命令输出返回给智能体。 |
| 沙盒 | 继承环境类，`execute()` 改为调用 AdaMAS 的 `run_confined`（工作区模式）。每次命令都写入越界日志的输入。 |

### 3.4 轨迹与越界扫描

- mini-swe-agent 的轨迹 JSON 里有每条命令的原文和输出。越界扫描需要加一个读取它的入口，和现在读 Codex rollout 的入口并列。扫描规则本身不改。
- 每次运行结束后，照常生成"沙盒越界警告"一节。

### 3.5 模型通道

- mini-swe-agent 通过 litellm 调用模型，既可以走 Chat Completions，也可以用它的 Responses 版模型类。我们的代理以前都是给 Codex 走 Responses 接口的。
- **开工前先确认**：用一个很小的请求，确认 `gpt-5.6-luna` 在代理的 Chat Completions 接口上可用。不可用时改用 Responses 版模型类。

### 3.6 为什么不用 smolagents

- smolagents 1.26 的步数上限在运行开始时就固定，运行中改不了，不方便实现"追加预算"。
- 它的 CodeAgent 在本进程里执行 Python，和"每条命令单独放进沙盒执行"的做法冲突。
- 它的回调机制很完整，但新设计用不到规划步骤，优势发挥不出来。

## 4. 本项目自己要写的部分（按模块，不含实现细节）

**轮回之内**

1. **预算账本**：
   - 记录各项预算的剩余、领用、报账、结转，以及每一次申请和决定；
   - 另外分开记三本账：出题账、重放账、管理开销；
   - 落盘为 JSON，运行中断后可以恢复。
2. **预算规划者**：
   - 输入是申请、账本快照、程序算出的进展指标、本题预算表，以及已启用的通用规则；
   - 决定四件事：追加批多少、继承失败修不修、是否提前收回额度、收紧修复或压缩上限；
   - 账本先算出机械上限，决定超出时截断。
3. **会话包装**：
   - 把构建者、出题者、修复者、规划者、进化者分别配成一个 mini-swe-agent 会话，包括提示、额度、工作区和沙盒；
   - 规划者和进化者没有工作区，也不能执行命令，只做一次推理并返回结构化输出。
4. **进展测量**：会话进行中每 N 步，把工作区拷一份快照，在快照副本上、在沙盒里跑一次本单元考卷，只记失败数；同时记录代码变化量（改动的行数和文件数）。这些数据不发给智能体，用时记为 harness 开销（DESIGN §8.4）。
5. **单元执行器**：
   - 流程是构建、过门（三栏）、至多 3 次修复、输出代码（DESIGN §4）；
   - 保存每个单元开始时的代码快照，以及提交时每条用例的结果。
6. **提交检查**：按 DESIGN §7 实现，只观测（本文 §2.4）。

**轮回之间**

7. **出题阶段**：在所有轮回之前，为每个单元出一次题，然后冻结；考卷带哈希，每个轮回开始前核对哈希。
8. **诊断**：从账本和进展记录算出 DESIGN §8.4 的八项诊断，以及 submittable 和轮回得分。
9. **预算进化者**：
   - 读预算表、轮回摘要和诊断，提出新表和 0–2 条通用规则；
   - 提议要过机械校验：总和、保底、改动幅度 ±30%；
   - 按接受规则（超过 ε_noise）保留新表或回滚。
10. **规划者状态**：每道题一张预算表（带版本），加上通用规则库和轮回摘要；全部存在构建者等智能体读不到的目录里。
11. **单元重放**：从某个单元的快照出发，用指定额度重跑这个单元若干次，比较本单元考卷的结果；花费记在重放账上。

**其他**

12. **运行驱动**：按轮回、按单元串行执行，记账，运行后评分和越界扫描，作废重跑。
13. **正对照**：仿照 AdaMAS 的 `scripts/pipeline_positive_control.py` 写一个本项目的版本。用小合成题、埋入已知错误，用脚本代替智能体做固定修改，检查以下几点：
   - 门能发现埋入的错误；
   - 修复后能过门；
   - 预算截停和结转正确；
   - 规划者的批复会被机械上限截断；
   - 三栏分栏正确：脚本故意弄坏一个早先过门的功能，应当记在第三栏；故意留下一个早先没过的失败，应当记在第二栏；
   - 提交检查能区分"能导入"和"不能导入"两种合成代码；
   - 进化者的提议如果超出改动幅度或总和，会被机械校验拒绝；
   - 冻结考卷的哈希不符时，拒绝开始轮回。

   整个过程不调用模型，任何改动流水线后都要先过它。
